# Kirameku-li 第三阶段：原作者信息清理与基础个性化设计

> 状态：设计已由用户逐项确认并正式锁定  
> 阶段目标：在不删除历史业务数据、不扩张为完整平台重构的前提下，完成原作者身份清理、公开内容隔离、个人品牌落地和基础项目展示。  
> 建议分支：`feat/original-author-cleanup-basic-personalization`

---

## 1. 背景与目标

Kirameku-li 已完成可运行基线修复，当前前台、后端与管理后台可以独立构建和启动。第三阶段不再继续做底层救火，而是把项目从“可运行的上游博客副本”转变为属于“晚”的个人站点。

本阶段必须同时解决四类问题：

1. 前台、后台、配置、静态资源和初始化数据中仍存在原作者身份信息。
2. 原作者的文章、动态、相册和访问统计不能继续作为新站点的公开内容。
3. 新站点需要形成统一的个人品牌、首页、项目页、关于页和内容空状态。
4. 历史数据仍需由管理员保留和管理，不能通过简单删除数据库完成清理。

## 9. 公共内容访问控制

### 9.1 唯一配置源

公开模块开关由后端环境变量统一读取，前端不得自行维护另一套安全开关。

环境变量：

```env
PUBLIC_POSTS_ENABLED=false
PUBLIC_POST_SLUG_ALLOWLIST=
PUBLIC_CHATTERS_ENABLED=false
PUBLIC_ALBUMS_ENABLED=false
```

后端提供只读公共站点配置接口，建议：

```http
GET /api/site/public-config
```

建议响应：

```json
{
  "contentVisibility": {
    "posts": false,
    "chatters": false,
    "albums": false
  },
  "publicPostSlugs": [],
  "siteStats": {
    "launchDateConfigured": false
  }
}
```

禁止在响应中泄露：

- 管理员配置
- 私有文章 slug
- 数据库内部信息
- 密钥
- 后台地址配置

### 9.2 文章规则

环境变量：

```env
PUBLIC_POSTS_ENABLED=false
PUBLIC_POST_SLUG_ALLOWLIST=
```

语义：

- `PUBLIC_POSTS_ENABLED=true`：所有符合现有发布条件的文章可公开。
- `PUBLIC_POSTS_ENABLED=false`：只有白名单中且本身符合发布条件的文章可公开。
- 当前白名单为空，所以所有历史文章和新草稿均不公开。
- 白名单值按逗号分隔，解析时去除空格和空项。
- 白名单不能让 `draft` 文章公开。

所有公开文章入口必须使用同一可见性规则：

- 文章列表
- 分页
- 文章详情
- 分类列表
- 分类文章计数
- 首页最新文章
- 搜索
- 公共统计
- 相关文章
- RSS / sitemap（如存在）
- Open Graph / metadata 预取（如存在）

非公开文章详情统一返回 `404`，不区分“不存在”与“存在但不可公开”。

集合接口建议：

- 无公开文章时返回正常空集合
- 不返回历史文章数量
- 不返回可推断旧内容存在的分类计数

管理员接口完全不受此规则影响。

### 9.3 动态与相册

关闭时：

- 前端导航和首页不展示
- 公共集合接口不返回历史数据
- 公共详情返回 `404`
- 公共统计不返回历史计数
- 直接访问页面路由返回 `404`
- 管理员后台仍能查看和管理

数据库中的历史记录不修改、不删除、不批量改状态。

## 10. 公开统计隔离

环境变量：

```env
PUBLIC_STATS_NAMESPACE=kirameku-wan-v1
SITE_LAUNCH_DATE=
```

规则：

- 原作者历史统计继续保留。
- 新站点访问量使用新的命名空间，从 0 开始。
- 公共统计只读取新命名空间。
- 管理后台仍可读取完整历史统计。
- `SITE_LAUNCH_DATE` 在第一次正式公网部署时填写。
- 未配置或格式无效时，前台隐藏运行时间。
- 禁止使用本地启动时间、代码合并时间或仓库创建时间代替。
- 运行时间按站点既有时区约定计算，不应因客户端时区造成负数或跳变。

公开页面只展示：

- 访问量
- 运行时间（已配置时）

```powershell

```

行为：

- 读取本地 Markdown
- 解析 YAML Front Matter
- 首次导入必须包含固定 `slug`
- `title` 优先读取 Front Matter，缺失时读取第一个一级标题
- `summary`、`category`、`tags` 从 Front Matter 读取
- 创建文章时强制状态为 `draft`
- 重复导入时按 `slug` 更新原草稿
- 不创建重复文章
- 已发布文章默认拒绝覆盖
- 不自动加入公开白名单
- 不自动发布
- 输出文章 ID、slug 和“创建/更新”结果
- 不在日志中输出完整正文

title: 我的 SecondBrain 工作流

summary: 我如何用 Obsidian、ChatGPT 与 Codex 管理学习和项目。
category: 方法与实践

# 我的 SecondBrain 工作流

错误场景必须终止且不产生半成品数据：
